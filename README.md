# tytup-backend

Минималистичный self-hosted бэкенд видеохостинга на Node.js: принимает загрузку видео, перекодирует его в HLS через ffmpeg, делает превью, хранит метаданные в PostgreSQL и раздаёт поток плееру.

Около 500 строк TypeScript на голом `http` из Node, без Express/Nest и без облачных сервисов.

## Зачем это нужно

- **Своё видео на своём сервере.** Не нужно зависеть от YouTube/VK/Rutube, их блокировок, рекламы, рекомендаций и правил модерации. Видео лежит у вас, ссылки ваши.
- **HLS «из коробки».** Загруженный файл любого формата, который понимает ffmpeg, превращается в `.m3u8` + сегменты `.ts`. Такой поток играет в браузере (hls.js, Safari нативно), на мобильных и в Smart TV, а также нормально проходит через CDN и nginx.
- **Маленький и понятный код.** Весь путь «загрузка → перекодирование → отдача» читается за вечер. Это хорошая основа, чтобы встроить видео в свой продукт: корпоративный портал, обучающую платформу, внутреннюю базу знаний, сайт сообщества.
- **Шифрованный и открытый HLS рядом.** Один и тот же сервер раздаёт как обычные потоки, так и зашифрованные AES-128. Отдельные сегменты зашифрованного видео без ключа не воспроизводятся. См. [демо шифрования](#шифрование-hls-aes-128-демо).
- **Минимум зависимостей.** Нужны Node.js и PostgreSQL. Бинарник ffmpeg ставится через npm (`@ffmpeg-installer/ffmpeg`).
- **Учебный пример.** Можно посмотреть, как без фреймворков устроены потоковая загрузка multipart (busboy), запуск ffmpeg, HLS-раздача с gzip и TypeORM.

## Как это работает

```
клиент ──POST /upload-video──▶ raw-videos/<id>.<ext>
                                      │
                                      ▼  ffmpeg (H.264 baseline, 1080p, сегменты по 10 с)
                               videos/<id>/output.m3u8 + *.ts
                               previews/<id>.jpg      (кадр на 10-й секунде)
                                      │
                                      ▼
                               PostgreSQL: video_info (имя, описание, url, превью, дата)

плеер ──GET /streams/<id>/output.m3u8──▶ HLS-сервер (gzip для манифеста)
```

## Быстрый старт

Нужны Node.js 20.6+ и PostgreSQL 12+.

```bash
git clone <repo-url> tytup-backend
cd tytup-backend
npm install

mkdir -p videos raw-videos previews
cp .env.example .env              # заполните DB_PASSWORD и PUBLIC_URL

# режим разработки (ts-node + nodemon), переменные из окружения
export $(grep -v '^#' .env | xargs) && npm run dev

# продакшен
npm run build
node --env-file=.env build/index.js
```

Таблица `video_info` создаётся автоматически при первом запуске (TypeORM `synchronize: true`).

## Конфигурация

Все настройки задаются переменными окружения, образец лежит в [.env.example](.env.example).

| Переменная           | По умолчанию            | Описание                                                     |
| -------------------- | ----------------------- | ------------------------------------------------------------ |
| `PORT`               | `8001`                  | Порт HTTP-сервера                                            |
| `HOST`               | `0.0.0.0`               | Адрес, на котором слушает сервер                             |
| `PUBLIC_URL`         | `http://localhost:8001` | Публичный адрес, из которого строятся ссылки на видео и превью |

| `DB_USERNAME`        | `postgres`              | Пользователь БД                                              |
| `DB_PASSWORD`        | пусто                   | Пароль БД                                                    |
| `DB_NAME`            | `tytup`                 | Имя базы                                                     |

## API

Все ответы приходят в JSON. Ошибки сейчас тоже возвращаются со статусом `200` и полем `error`.

### `POST /upload-video`

`multipart/form-data`:

| Поле          | Тип  | Обязательно | Описание                                            |
| ------------- | ---- | ----------- | --------------------------------------------------- |
| `video`       | файл | да          | Видео с MIME-типом `video/*`                        |
| `name`        | текст | нет        | Название; по умолчанию берётся имя файла            |
| `description` | текст | нет        | Описание                                            |

```bash
curl -F "video=@clip.mp4;type=video/mp4" -F "name=Мой ролик" -F "description=Тест" \
  http://localhost:8001/upload-video
```

```json
{ "result": "Video #3f1c…  successfully uploaded. And will be transcoding as soon as possible." }
```

Перекодирование идёт в фоне: запись в БД появляется только после того, как ffmpeg закончит работу.

### `GET /video-list`

```json
{ "result": { "items": [ { "id": "…", "name": "…", "url": "…", "preview": "…", "createdAt": 1688650000 } ], "count": 1 } }
```

Записи отсортированы по `createdAt`. Параметры `skip` и `take` уже читаются из query, но пагинация пока не применяется.

### `GET /video-info/:id`

```json
{ "result": { "id": "…", "name": "…", "description": "…", "url": "…", "preview": "…", "author": "…", "createdAt": 1688650000 } }
```

### `GET /streams/:id/output.m3u8`

HLS-манифест и сегменты из каталога `videos/`. Манифест отдаётся в gzip, если клиент его поддерживает. Для зашифрованных видео тут же отдаётся ключ `/streams/:id/enc.key`.

## Шифрование HLS (AES-128): демо

Проект показывает, что на одном сервере могут жить зашифрованные и открытые видео:

- видео, загруженные через `/upload-video`, перекодируются **без шифрования**;
- отдельное демо-видео шифруется скриптом `encrypt-video`. Его манифест содержит `#EXT-X-KEY`, а сегменты `.ts` зашифрованы AES-128-CBC.

Встроенный плеер (hls.js, Safari) сам читает `#EXT-X-KEY`, скачивает ключ и расшифровывает поток. Если же скачать отдельный сегмент `.ts`, ни один плеер его не воспроизведёт.

### Как зашифровать видео

```bash
npm run encrypt-video -- path/to/clip.mp4 encrypted-demo
```

Скрипт [src/scripts/encrypt-video.ts](src/scripts/encrypt-video.ts):

1. генерирует случайный 16-байтный ключ в `videos/<id>/enc.key` и случайный IV;
2. собирает временный файл `enc.keyinfo` (URI ключа, путь к ключу, IV);
3. перекодирует видео с теми же параметрами, что и основной пайплайн, плюс `-hls_key_info_file`.

Результат будет доступен по адресу `${PUBLIC_URL}/streams/<id>/output.m3u8`.

> Если делаете это вручную в Windows, не создавайте ключ через `openssl rand 16 > enc.key` в PowerShell. Перенаправление `>` запишет байты как текст UTF-16 с BOM, и файл получится длиной 38 байт вместо 16. Используйте `openssl rand -out enc.key 16`.

### Что это защищает, а что нет

В демо ключ **намеренно отдаётся любому** по `/streams/<id>/enc.key` без проверок. Задача демо — отладить сам механизм шифрования, логики доступа к ключу здесь нет.

| Защищено | Не защищено |
| --- | --- |
| Сегменты `.ts`, скачанные по отдельности, не воспроизводятся | Ссылку на `output.m3u8` можно открыть в VLC или `ffplay`: плеер сам скачает ключ |
| Кэш CDN и прокси хранит только зашифрованные данные | Ключ видно во вкладке Network в DevTools |

Чтобы смотреть видео можно было только в своём плеере, ключ нужно отдавать по проверке доступа. Например, через отдельный эндпоинт с короткоживущим подписанным токеном, привязанным к сессии пользователя. Ключи при этом должны храниться вне каталога, который раздаётся как статика. Даже так авторизованный пользователь может сохранить ключ. Полную защиту даёт только DRM (Widevine, FairPlay), и то без защиты от записи экрана.

## Продакшен за nginx

В БД записываются ссылки вида `${PUBLIC_URL}/videos/<id>/output.m3u8` и `${PUBLIC_URL}/previews/<id>.jpg`. Раздавать каталоги `videos/` и `previews/` удобнее всего статикой nginx, а API проксировать в Node:

```nginx
location /videos/   { alias /srv/tytup-backend/videos/; }
location /previews/ { alias /srv/tytup-backend/previews/; }
location /          { proxy_pass http://127.0.0.1:8001; client_max_body_size 50m; }
```

## Структура проекта

```
src/
  index.ts                 HTTP-сервер, CORS и маршрутизация
  config.ts                настройки из переменных окружения
  data-source.ts           подключение к PostgreSQL (TypeORM)
  entities/video-info.ts   сущность видео
  upload-video-handler.ts  приём multipart-загрузки
  video-list-handler.ts    список видео
  video-info-handler.ts    карточка видео
  video-processing/        ffmpeg: HLS и превью, общие параметры кодирования
  hls-server/              раздача .m3u8 / .ts / .key / .jpg
  scripts/encrypt-video.ts демо: зашифрованный HLS (AES-128)
```

## Ограничения и что стоит доделать

Проект в статусе MVP. Прежде чем запускать его в открытый интернет, учтите:

- **Нет авторизации.** Загружать видео может любой, у кого есть доступ к `/upload-video`. Закройте эндпоинт на уровне nginx или добавьте проверку токена.
- **Нет очереди.** Каждая загрузка сразу запускает отдельный процесс ffmpeg, поэтому при параллельных загрузках сервер легко перегрузить.
- Ключи шифрования HLS отдаются без проверки доступа (см. [демо шифрования](#шифрование-hls-aes-128-демо)). При загрузке через API видео не шифруются.
- Видео всегда масштабируется в 1920×1080, адаптивного битрейта (несколько качеств) нет.
- `duration` и `views` пока не вычисляются и сохраняются как `N/A`.
- HTTP-статусы ошибок не проставляются, пагинация в `/video-list` не работает.
- Схема БД создаётся через `synchronize: true`, миграций нет.
- Тестов нет.

Pull request'ы с любым из этих пунктов приветствуются.
